# DT Core Writing Rules

When you use this skill, obey these rules.

## Words and Nouns

### Approved Words

Use simple words. A word must have only one approved meaning and one approved part of speech.

### Technical Nouns and Verbs

You can use technical nouns (for example, `server`, `software`) and technical verbs (for example, `format`, `reboot`) if you use them correctly.

### Multi-Word Nouns

Do not use multi-word nouns of more than three words.

Non-DT: Local area network connection configuration.
DT: Configuration of the local area network connection.

### No Slang, Jargon, or Latin

Do not use slang, jargon, or Latin abbreviations (do not use e.g., i.e., or etc.).

## Verbs and Tense

### Active Voice

Only use the active voice. The subject must do the action.

Non-DT: The files are deleted by the operating system.
DT: The operating system deletes the files.

### Approved Tenses

Only use the infinitive, the imperative form, the simple present tense, the simple past tense, the simple future tense, and the past participle form (as an adjective).

### Tenses That Are Not Approved

Do not use the present perfect tense (has adjusted), the past perfect tense (had adjusted), or progressive tenses (is adjusting).

### The -ing Form

Do not use words that have an -ing form to describe an action. You can use them only as technical nouns (for example, `Cleaning`, `Troubleshooting`).

### Imperative Form for Procedures

Write instructions in the imperative form.

Non-DT: The script can be started.
DT: Start the script.

## Sentences

### Sentence Length Limits

For procedural writing (instructions), use a maximum of 20 words in each sentence. For descriptive writing (information), use a maximum of 25 words in each sentence.

### One Instruction in Each Sentence

Write only one instruction in each sentence. You can write more than one instruction if the actions occur at the same time.

DT: Remove and discard the broken cable.

### Condition Before Command

If a special condition is necessary for a work step, write the condition first. Then, put a comma.

Non-DT: Set the variable to TRUE when the process completes.
DT: When the process completes, set the variable to TRUE.

### No Contractions or Omitted Words

Write all words in full (for example, write `do not`, not `don't`). Do not omit articles (for example, `a`, `an`, `the`) to make the sentence shorter.

## Paragraphs and Structure

### Paragraph Length

Make sure that no paragraph has more than six sentences.

### Paragraph Topic

Make sure that each paragraph has only one topic. Write a clear topic sentence at the start of the paragraph.

### Vertical Lists

Use a vertical list for complex texts, multiple conditions, or a minimum of three parts.

## Safety Instructions (Warnings and Cautions)

### WARNING

Use a warning to show that there is a risk of injury, death, or severe data loss.

### CAUTION

Use a caution to show that there is a risk of damage to equipment or minor data corruption.

### Structure

When you write a safety instruction, do these three steps:

1. Identify the risk level (WARNING or CAUTION).
2. Give a clear command or condition.
3. Give an explanation to show the risk.

Example: WARNING: DO NOT DELETE THE PRIMARY DATABASE. THIS ACTION WILL CAUSE PERMANENT DATA LOSS.

## Miscellaneous

### Punctuation

Do not use the semicolon (`;`). Write two separate sentences.

### Connecting Words

Use connecting words (for example, `and`, `but`, `then`, `thus`) and connecting phrases (for example, `as a result`). These words and phrases give the text a logical structure
